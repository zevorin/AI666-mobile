# 移动端作品点赞动画复用设计

## 目标

移动端图片、视频作品详情的主点赞按钮复用 Web 端闪念点赞反馈：点赞时心形图标压缩回弹，8 个暖金粒子从图标中心径向散开；取消点赞只更新状态并清理残留动画。关注、收藏、评论点赞不受影响。

## 方案

1. 只复制图标缩放：改动最小，但会丢失 Web 端最有辨识度的粒子反馈，不符合“相同动画”。
2. 移植完整动画：复用 Web 端的 520ms 回弹关键帧、8 向粒子轨迹、错峰延迟和 680ms 清理逻辑，并适配移动端心形图标与暖金令牌。采用此方案。
3. 跨项目抽象共用组件：能减少重复，但 Web 与移动端是两个独立静态工程，当前只复用一处交互，改造成本过高。

## 实现边界

- 图片详情与视频详情的主点赞按钮增加专用标记和图标容器。
- 通用 `data-mobile-toggle` 状态、计数和 Toast 逻辑保持不变；只有专用点赞按钮会创建粒子节点。
- 连续点击时先取消旧计时器和粒子，再开始下一次动画，避免节点累积。
- 取消点赞时立即清理庆祝状态，不播放反向粒子动画。
- `prefers-reduced-motion: reduce` 下不创建粒子、不执行图标回弹，点赞状态与计数仍正常更新。

## 验收

- 图片、视频详情首次点赞：计数 +1、按钮进入选中态、心形回弹、8 个粒子散开、Toast 正常。
- 再次点击：计数恢复、选中态取消、无残留粒子或动画类。
- 快速连续点击不累积粒子节点或计时器。
- 关注与收藏仍只更新原有状态，不触发点赞动画。
- 减弱动效环境中无动画，但状态更新可用。

## 完整显示修正

移动端全局存在禁用动画的高优先级规则，因此动画触发器需要较高优先级和 `!important`。粒子的方向、颜色和延迟不能放进同一个高优先级基础规则，否则低优先级的 `:nth-child()` 方向配置会被覆盖，8 个粒子将完全重叠。

修正后，基础几何与默认方向使用普通 `.mobile-like-particle` 规则，8 个方向继续由 `:nth-child()` 覆盖；高优先级触发器只负责恢复 `animation`。这样既能越过全局禁用规则，又能保证 8 个粒子沿不同方向完整散开。
